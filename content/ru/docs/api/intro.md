Здесь и следующих подразделах мы расскажем как использовать API нашей панели управления Интернет-радио для получения информации о состоянии эфира и других данных программными методами. Используя наш API Вы можете строить свои собственные скрипты, приложения и модули для сайта своего радио, мобильного приложения и любой интеграции, где требуется программное взаимодействие с сервером радио.

Для работы с API у Вас уже должна быть установлена и настроена наша Панель Управления Интернет-радио. Для работы с API Вы должны знать URL своей панели управления: тот адрес, по которому Вы обычно заходите в интерфейс вещателя, где Ваши каналы, плей-листы, сетка вещания и прочие разделы.

URL адрес API находится по адресу: **<адрес Вашей панели на сервере>/api/<версия api>**, например: 

[https://demoaccount.radio-tochka.com:8080/api/v2/](https://demoaccount.radio-tochka.com:8080/api/v2/) 


Большинство запросов и ответов используют JSON. [История эфира](/docs/api/history/#api-history) также поддерживает JSONP. Методы для медиафайлов, выгрузок, виджетов и публичных страниц могут использовать другие форматы, указанные в их описаниях. Для правильной работы API мы настоятельно рекомендуем иметь настроенную и рабочую поддержку протокола **HTTPS** на стороне сервера, а в тех случаях, где необходима [Авторизация](/docs/api/auth/) для API запросов - **HTTPS** протокол критически необходим для защиты передачи токенов авторизации.


Пример API запроса на языке программирования Python, который получает [историю эфира](/docs/api/history/#api-history) (1 последний трек, он же является текущим на радио, который играет прямо сейчас), которые играли на сервере **1**:

{{< highlight python  >}}

import requests

response = requests.get("https://demoaccount.s02.radio-tochka.com:8080/api/v2/history/?limit=1&offset=0&server=1")
print(response.json())

{{< / highlight >}}

## Правила работы с запросами

Используйте пути в указанном виде, включая завершающую косую черту там, где она есть. Вместо обозначений в фигурных скобках, например `{id}`, подставляйте фактические идентификаторы. В списках, относящихся к станции, `?server=1` обычно фильтрует результаты. При создании записи [станцию задаёт](/docs/api/servers/#api-stations) поле JSON `server`.

Для передачи JSON используйте `Content-Type: application/json`, для загрузки файлов — `multipart/form-data`. Стандартные методы списка возвращают массив, если не применяется пагинация. При пагинации с `limit` и `offset` объект содержит `count`, `next`, `previous` и `results`. Если соседней страницы нет, в поле ссылки возвращается `null`. У отдельных методов свои параметры пагинации и поля ответа.

Стандартное создание возвращает HTTP 201 и сохранённый объект. Изменение обычно возвращает HTTP 200 с объектом, а удаление — HTTP 204 без тела. Ошибки проверки обычно возвращают HTTP 400 с сообщениями по полям. При отсутствии доступа возможен HTTP 401 или 403, при отсутствии записи — HTTP 404. Параметры и особенности ответов указаны в описании каждого метода.
