Большинство запросов к API нацелены на получение информации о состоянии радио, но в некоторых случаях есть необходимость:
- получить информацию, которая является не публичной, например, [список диджеев](/docs/api/djs/#api-djs) на радио с паролями доступа
- внести изменения на сервере радио, например, [добавить новый канал](/docs/api/channels/#api-channels), сервер, [создать плей-лист](/docs/api/playlists/#api-playlists) и так далее.

В таких случаях API потребует авторизацию при запросе.
Наша платформа Интернет-радио поддерживает стандартный механизм авторизации для API: ключи, которыми вы можете управлять в разделе "Настройки" -> "API ключи" панели управления Интернет-радио.

В целом процесс выглядит следующим образом:
- в платформе заводится новый ключ API
- этот ключ указывается при выполнении запросов к API в заголовке HTTP
- API проверяет наличие ключа в запросе, проверяет его корректность и выполняет запрос если ключ валиден.

Обращаем внимание на то, что при работе с API ключами критически необходима работа по протоколу HTTPS, иначе API ключи могут быть скомпрометированы.

#### Пример использования ключа.

В разделе "Настройки" -> "API ключи" Панели Управления Интернет-радио был создан ключ: **YOUR_API_KEY**. В Вашем случае необходимо самостоятельно перейти в этот раздел, завести собственный ключ и использовать его, в статье указанный ключ используется **только для демонстрации** и не будет работать с Вашим API!

Для демонстрации создадим на сервере с ID 1 случайный плейлист с названием "Test Playlist". Запрос выполняется методом POST по URL [`/api/v2/playlists/`](/docs/api/playlists/#api-playlists):

{{< highlight python  >}}

import requests

payload = {
   "name":"Test Playlist",
   "is_random":True,
   "server":1
}

headers = {"SC-API-KEY": "YOUR_API_KEY"}
response = requests.post("https://demoaccount.s02.radio-tochka.com:8080/api/v2/playlists/", headers=headers, json=payload)

{{< / highlight >}}

Передавайте ключ в заголовке `SC-API-KEY`. Методы с обязательной авторизацией отклоняют запросы без действующего ключа или JWT-токена.

Любой ключ можно отозвать, система позволяет создавать любое количество ключей и для каждого из них можно указать срок действия.

Ключи API принимают только методы с поддержкой этого заголовка. Создание и отзыв ключей через API описаны в разделе [настроек и доступа](/docs/api/settings/#api-api-keys).

## Вход в панель вещателя

Передавайте учётные данные и токены по HTTPS. При входе в панель управления вы получаете JWT-токен. Ключи API и [токены слушателей](/docs/api/listeners/#api-listener-login) описаны отдельно.

```http
POST /api/v2/api-token-auth/
```

```json
{
  "username": "show-host",
  "password": "<panel password>"
}
```

Ответ содержит `access` и `refresh`. Передавайте токен доступа в заголовке `Authorization: JWT <access>`. После истечения срока действия токена войдите снова через этот метод. Если для аккаунта включена [двухфакторная аутентификация](/docs/api/auth/#api-two-factor), добавьте строку `otp` с текущим кодом или одноразовый `recovery_code`. При отсутствии кода возвращается HTTP 400 с `detail: otp_required`.

<div class="api-block">
<b>Путь</b> /api/v2/auth_user/<br/>
<b>Методы HTTP</b> GET<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

[Текущий пользователь панели](/docs/api/panel-users/#api-panel-profile), роли, действующие `permissions`, признак владельца и `access_expires_at`. Требуется JWT-токен.

<div class="api-block">
<b>Путь</b> /api/v2/change_password/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Требуется JWT-токен. Передайте `old_password` и `new_password`. Возвращает новый `token` и отзывает прежние токены.

<div class="api-block">
<b>Путь</b> /api/v2/remind_password/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> Без авторизации<br/>
</div>

Передайте `email` и необязательный `lang` для запроса сброса пароля. При принятии запроса возвращается HTTP 200 без тела.

<div class="api-block">
<b>Путь</b> /api/v2/tokenized_change_password/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> Без авторизации<br/>
</div>

Передайте `u` и `t` из ссылки в письме и новый `password`. Возвращает `{}`.

## Двухфакторная аутентификация

Для этих методов нужен JWT-токен текущего пользователя.

<div class="api-block">
<b>Путь</b> /api/v2/totp/status/<br/>
<b>Методы HTTP</b> GET<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Возвращает `enabled`, `confirmed` и `recovery_codes_remaining`.

<div class="api-block">
<b>Путь</b> /api/v2/totp/setup/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Начинает настройку. Возвращает `secret`, ссылку настройки `uri` и `qr_svg`.

<div class="api-block">
<b>Путь</b> /api/v2/totp/confirm/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Передайте `code` из приложения-аутентификатора. Включает двухфакторную защиту и возвращает одноразовые `recovery_codes`.

<div class="api-block">
<b>Путь</b> /api/v2/totp/disable/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Передайте текущий `password` для отключения двухфакторной защиты. Возвращает `{}`.

<div class="api-block">
<b>Путь</b> /api/v2/totp/regenerate/<br/>
<b>Методы HTTP</b> POST<br/>
<b>Авторизация</b> JWT-токен<br/>
</div>

Заменяет ранее выданные коды восстановления. Возвращает новые `recovery_codes`.

## Значения в примере авторизации

В примере создаётся плейлист для станции с ID 1. `is_random: true` включает случайный порядок, `false` — последовательный. Значения `otp` и `code` — строки из приложения-аутентификатора. Сохраняйте ведущие нули.
